# SDKs

trueseal-sync is written in Rust. The SDKs below wrap that one Rust core through native bindings, so each language gets an idiomatic, statically-typed API without anyone having to re-implement the protocol three times and pray the implementations agree.

API reference, install instructions and integration examples live in each repo's README. This page is just the entry point — pick a platform, follow the link.

All SDKs expose a stable opaque Message ID with each received blob. Relay delivery is at least once, so applications persist that ID with their own state and ignore an ID already processed. Payloads remain opaque to TrueSeal.

## Available

All three SDKs are in the Developer Preview. They share one API shape and one core build, release together, and their API may change before 1.0.

| SDK | Status | Repo |
|---|---|---|
| **Swift** | Developer Preview | [github.com/julianbonomini/trueseal-sync-swift](https://github.com/julianbonomini/trueseal-sync-swift) |
| **Kotlin** (Android) | Developer Preview | [github.com/julianbonomini/trueseal-sync-kotlin](https://github.com/julianbonomini/trueseal-sync-kotlin) |
| **TypeScript** | Developer Preview | [github.com/julianbonomini/trueseal-sync-ts](https://github.com/julianbonomini/trueseal-sync-ts) |

### Swift

iOS and macOS, distributed through Swift Package Manager. Wraps the Rust xcframework through UniFFI. The Hush example apps use it on iOS and macOS.

### Kotlin

Android only, distributed through Maven Central as `dev.trueseal:trueseal-sync`. Same UniFFI bindings against the same Rust core. Kotlin outside Android isn't a supported target in the preview. The Hush example app uses it on Android.

### TypeScript

Node.js 20 or later, with native bindings rather than WASM. Browser is **not** a target. The protocol speaks raw TCP to the relay, and browsers can't open raw TCP sockets.

## Rust

If you're already on Rust, skip the wrappers and use [`trueseal-sync`](https://github.com/julianbonomini/trueseal-sync) directly. There's no "Rust SDK" because there's nothing left to wrap.

## Other languages

- **Go** — planned, post-launch. The relay is already Go, so a Go sync SDK is the natural next thing.
- **Anything else** — implement [trueseal-protocol](/docs/reference/protocol). The wire spec is the only contract that matters; if your client speaks it, any conforming relay will talk back.
