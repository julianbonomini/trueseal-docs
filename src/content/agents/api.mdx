# SDK API reference

The three SDKs expose one API (trueseal-sync ADR-0028). Each entry gives the shared signature, then each platform's spelling where it differs. Swift uses `async throws`, Kotlin uses `suspend` with exceptions, and TypeScript uses Promises. Errors, events and delivery issues are on [Errors and events](/agents/errors-and-events). Values are on [Limits](/agents/limits) and [Versions and Relay Address](/agents/versions-and-relay-address).

## What the API does not do

- Conflict resolution is the app's job. The library delivers every message and never merges them (trueseal-sync ADR-0003).
- Application payload versioning is the app's job. Bodies are opaque bytes, and the Transport and End-to-End Versions cover the protocol only (trueseal-sync ADR-0003, trueseal-sync ADR-0022).
- Ordering holds per sender only (trueseal-sync ADR-0026).
- The library sets no handler timeout (trueseal-sync ADR-0026).
- The app never acks a message. The library acks after the handler returns (trueseal-sync ADR-0026).
- A join request has no reject call. An unaccepted request disappears when the pairing window closes (trueseal-sync ADR-0028).
- Events and delivery issues arrive through handlers, and the SDKs offer no native streams (trueseal-sync ADR-0028).
- `send()` takes bytes only and has no text overloads (trueseal-sync ADR-0028).
- The library never splits a message across frames (trueseal-sync ADR-0025).
- Versions are never negotiated (trueseal-sync ADR-0022).
- The Developer Preview has no public Rust API (trueseal-sync ADR-0030).
